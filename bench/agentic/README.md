# エージェントベンチ — pass@k を測る

既存の [BENCHMARK_RESULTS.md](../../BENCHMARK_RESULTS.md) は**単発QA**(MMLU/GSM8K 等)の
ベンチであり、FableT が本当に超えたい相手——**エージェントとしてのコーディング能力**——を
測っていない。ここはそれを測るための最小の土俵である。

## 何を測るか

各タスクは「壊れた(または未実装の)リポジトリ + 隠しテスト」で構成される。エージェントに
リポジトリを渡し、**隠しテストは見せずに**修正させ、終了後にテストを回して合否を機械判定する。

- **pass@1** — 1回試して通る確率。フロンティア(Fable 5)の土俵。
- **pass@k** — k回試して**1回でも**通る確率。FableT の土俵。ローカル推論は無料なので k は
  好きなだけ上げられる。**pass@k(FableT) > pass@1(Fable 5)** を示すことがこのベンチの目的。

k回の試行はそれぞれ独立(前の試行を見せない)。これは office のフル予算(best-of-N)が
実際に効くかどうかの直接の検証でもある。

## 使い方

```bash
# FableT(ローカル・無料)で k=3
./run.sh --agent fablet --k 3

# 比較対象: 素の claude(本物のAnthropic = クレジット消費する)で k=1
./run.sh --agent claude --k 1
```

結果は `results/<agent>-k<k>-<timestamp>.json` に出る。集計は `./score.sh <結果ファイル>`。

> **注意**: `--agent claude` は**クレジットを消費する**。比較のため意図的に使うとき以外は
> 実行しないこと。既定は `fablet`。

## タスクの追加

`tasks/<名前>/` を作り、次の3点を置く:

| ファイル | 役割 |
|---|---|
| `repo/` | エージェントに渡す作業ディレクトリ(壊れた状態のコード) |
| `prompt.txt` | エージェントへの依頼文。**隠しテストの中身に触れてはならない** |
| `verify.sh` | 隠しテスト。`repo/` の中で実行され、終了コード0なら合格 |

`verify.sh` は必ず `repo/` の外に置く(エージェントから見えると、テストを書き換えて
「通す」ことができてしまう。検証器を守ることがこのベンチの生命線である)。

## この土俵の限界

機械が判定できる仕事しか測れない。設計の趣味、命名の美しさ、ドキュメントの読みやすさは
測れないし、best-of-N も効かない。**FableT の優位はここまで**という境界を、この
ベンチは正直に示す。
